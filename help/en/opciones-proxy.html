Options: Proxy/Socks

  • No proxy/socks: direct connection.
  • Use system settings: the proxy configured in Windows.
  • Use automatic configuration script: a PAC script (its address).
  • Manual proxy/socks configuration: server, port and, if the proxy requires it, user name and password (stored encrypted), and the protocols that use it (http, https, ftp). Get from system copies the Windows proxy. Advanced... / Socks...: one proxy per protocol (HTTP, HTTPS and FTP, each with its own server, port, login and password; without its own server it uses the one on the page), the SOCKS server (Socks 5 or Socks 4; with Proxy DNS the SOCKS server resolves host names, without it this computer does), which is only used for the unchecked protocols, and the addresses that bypass the proxy. FTP goes through the HTTP proxy, which acts as the FTP client (with several connections if it supports ranges); it does not go through SOCKS, and encrypted FTP (ftps) always connects directly.
  • Use proxy/socks from the browser request: downloads coming from the browser that fail because the server cannot be reached (or because the configured proxy answers 407) are retried through the proxy the browser was using. It only works with a password-less HTTP proxy reported by the browser: in practice Firefox; Chromium (Chrome, Edge...) does not report it.
  • use FTP in PASV mode: on by default; if one mode fails, IDMClone tries once with the other.
Which protocols and proxy types IDMClone supports (http, https, ftp, SOCKS) is stated in the note on the Options page itself.
