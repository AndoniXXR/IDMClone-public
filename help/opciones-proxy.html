Opciones: Proxy/Socks

  • No hay proxy/socks: conexión directa.
  • Usar configuración del sistema: el proxy configurado en Windows.
  • Usar scripts de configuración automáticamente: un script PAC (su dirección).
  • Configuración manual de proxy/socks: servidor, puerto y, si el proxy lo pide, usuario y contraseña (se guarda cifrada), y los protocolos que lo usan (http, https, ftp). Obtener del sistema copia el proxy de Windows. Avanzado... / Socks...: un proxy para cada protocolo (HTTP, HTTPS y ftp, cada uno con su servidor, puerto, usuario y contraseña; sin servidor propio usa el de la página), el servidor SOCKS (Socks 5 o Socks 4; con Proxy DNS los nombres los resuelve el servidor SOCKS, sin él este equipo), que solo se usa para los protocolos no marcados, y las direcciones que no usan proxy. El FTP va por el proxy HTTP, que hace de cliente FTP (con varias conexiones si admite rangos); no pasa por SOCKS, y el FTP cifrado (ftps) va siempre directo.
  • Usar proxy/socks desde la petición de un navegador: para las descargas que vienen del navegador, si fallan por no llegar al servidor (o por un 407 del proxy configurado), se repiten por el proxy que usaba el navegador. Solo funciona con un proxy HTTP sin contraseña indicado por el navegador: en la práctica, Firefox; Chromium (Chrome, Edge...) no lo indica.
  • usar FTP en modo PASV: activado por defecto; si un modo falla, IDMClone prueba una vez con el otro.
Qué protocolos y tipos de proxy admite IDMClone (http, https, ftp, SOCKS) lo indica la nota de la propia página de Opciones.
